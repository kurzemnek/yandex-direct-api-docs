# Знания, данные и состояние

Одна компания использует один `knowledge_root` для SEO и рекламы. Перед записью
агент изучает существующую schema и её процедуру завершения. Справочник API
остаётся внешним источником, который подключается по необходимости.

## Что сохранять в проекте

- **Raw:** неизменные версии документов и снимков источников; source_id, дата,
  исходный адрес/путь и hash. Новый источник или версия сохраняется отдельно.
- **Wiki:** связанные карточки продуктов, аудиторий, метрик, фактов, решений и
  уроков. У утверждения есть основание, точное место, сущность и период.
- **schema / index / log:** правила базы, карта входа и история изменений.
  Имена и формат существующей базы сохраняются; новый дом может использовать
  `schema.md`, `Raw/`, `Wiki/`, `index.md`, `log.md`.
- **Операционное хранилище:** очереди, SQL/срезы, права, расходы, блокировки,
  намерения, квитанции и NOW. Миллионы строк не вклеиваются в смысловую Wiki.

## Три операции

**INGEST:** зарегистрировать версию источника, проверить повтор, выделить факты,
обновить связанные карточки и решения. Противоречие сохраняется явно; новая
версия не переписывает историю. Затронутые допуски требуют повторной проверки.

**QUERY:** ответить по основаниям; устойчивый полезный вывод, решение и важный
пробел сохранить в Wiki со ссылками. Чат не является единственным местом памяти.

**LINT:** проверить структуру, ссылки, достижимость, источники, датировки,
противоречия, устаревание и отсутствие закрытого в публичных материалах.

## Завершение записи

Использовать согласованный writer lock и процедуру восстановления своей базы.
Сначала все карточки/индекс/журнал, затем её штатная финализация. Квитанция с hash
финального снимка хранится снаружи изменяемого vault, чтобы не создавать цикл
«журнал → hash → журнал». Чужую команду финализации автоматически не копировать.

Публичные факты отделяются от закрытых условий и персональных данных. Реальные
экспорты, токены, CRM и внутренние пути не коммитятся в этот справочник. Локальное
обезличивание производится в рабочем контуре: таблица соответствий остаётся там;
пересечения и агрегаты сверяются после преобразования.

Это инженерный контракт адаптации, совместимый с идеей компилируемой LLM Wiki;
он не объявляет конкретные имена или поля требованиями автора исходного паттерна.
