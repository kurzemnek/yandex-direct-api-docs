# Обновления из upstream

В корне сохранён исходный снимок DragonSigh. Наша адаптация: `AGENTS.md`, вводный
блок README, `guide/`, `tools/`, `.gitignore`. Оригинальный README сохранён в
`guide/upstream/README.md`. Авторство и ссылки на первоисточник сохранены.

## Проверить новую версию

В локальной копии:

```bash
git remote -v
# Если upstream ещё не добавлен:
git remote add upstream https://github.com/DragonSigh/yandex-direct-api-docs.git
git fetch upstream
git log --oneline HEAD..upstream/main
git diff HEAD...upstream/main --stat
```

Команды выше не запускают рекламные операции. Новые инструкции и скрипты внешнего
репозитория сначала читаются как недоверенный вход. Не исполнять их автоматически.

## Принять обновление

Работать с чистым деревом в отдельной ветке. Сохранить текущий проверенный commit,
выполнить merge, осмысленно разрешить README-конфликт. Не затирать свои guide/tools.
Капча, HTTP-ошибка, пустой текст или страница с неподтверждённой версией не становятся
новой карточкой метода. Оригинальный снимок и исправления различаются в истории.

После выбора upstream commit обновить `guide/upstream.json`: base_commit,
snapshot_date и file hashes из этого commit; оригинальный README сохранить снова.
Затем `python3 tools/docs.py index` и `python3 tools/docs.py check`.
Пересмотреть `guide/CURRENT.md` и `guide/sources.json` по первичной документации.
Дата сверки отдельной страницы не становится датой обновления всего корпуса.

Если меняется метод, перечислить затронутые карточки/контракты и повторить их
локальные проверки. Настоящая интеграционная проба делается отдельно в рабочем
проекте и в пределах его прав. Расписаний и автоматического merge здесь нет.
