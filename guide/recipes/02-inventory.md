# 02. Получить инвентаризацию своего кабинета

[Начало](../START.md) · [Актуальность](../CURRENT.md) · [Доступ](01-connect.md) · [Далее: отчёты](03-reports.md)

**Вход:** подтверждённый доступ чтения, выбранный кабинет и среда, цель обзора.
**Политика агента:** сначала снимок, затем выводы; на этом шаге ничего не менять.

## Шаги

1. Зафиксировать время снимка, клиента, версию API и область охвата: все доступные
   кампании или согласованный поднабор. Состояния архива и исторические типы
   учитывать явно; «все» не обещать без проверки поведения фильтров метода.
2. Получить кампании с идентификаторами, именами, типами и состояниями.
   Запрашивать необходимые поля и параметры соответствующих типов.
3. Для найденных кампаний прочитать группы, объявления и условия показа;
   при поддержке типа — ключи, автотаргетинг, аудитории, минус-фразы,
   корректировки, стратегии, географию, расписание, цели и ссылки.
   Поддержку каждого сервиса и совместимость полей проверить в актуальной схеме.
4. Для каждой выборки пройти все страницы по контракту конкретного метода.
   Сохранить границы страниц, признаки продолжения, ошибки и недоступные поля.
   Не переносить механизм пагинации одного сервиса на все остальные.
5. Связать объекты по идентификаторам, проверить дубликаты и отсутствующие связи.
   Снимок нескольких запросов может отражать параллельные изменения кабинета:
   подозрительные расхождения перепроверить чтением.
6. Построить таблицу «что есть → что включено → куда ведёт → что измеряется».
   Не считать `OFF`, архив, черновик и ошибку доступа одним состоянием.
7. Отдельно отметить текущую доступность изменения каждого типа: объект может
   читаться через API, но его создание уже может быть недоступно.

## Выход

Приватный снимок и краткая сводка:

| Раздел | Что сохранить |
| --- | --- |
| Охват | кабинет, среда, время, фильтры, полнота страниц |
| Структура | кампании → группы → объявления → условия |
| Настройки | тип, стратегия/бюджет, гео, корректировки, цели |
| Материалы | форматы, тексты, изображения/креативы, URL/UTM |
| Пробелы | не запрошено / не поддержано / нет прав / ошибка |

В публичный пример переносить только синтетические объекты. Fixture проверяет
разбор снимка, но не доказывает, что реальный кабинет существует или доступен.

## Критерии готовности

- Числа в сводке воспроизводятся из снимка; полнота каждой сущности обозначена.
- Пустой успешный результат записан как «объектов в этой выборке нет».
- Недоступный сервис и незавершённая пагинация не выданы за отсутствие объектов.
- Расход, остаток денег и API-баллы не смешаны; коммерческие данные не опубликованы.

## Блокеры

Нет доступа к клиенту, неподдерживаемый тип/поле, оборванная выборка, исчерпана
квота или кабинет меняется во время снимка. Выдать частичный снимок с точными
границами; остановить зависимые выводы, но сохранить подтверждённые данные.

## Проверенные основания API

[Campaigns.get](https://yandex.ru/dev/direct/doc/ru/campaigns/get) задаёт фильтры,
поля и страницу выборки. Различия состояний и денежных единиц описаны в
[объекте кампании](https://yandex.ru/dev/direct/doc/ru/objects/campaign).
[API-баллы](https://yandex.ru/dev/direct/doc/ru/concepts/units) — отдельная квота.
Проверено 2026-11-12; сервисы дочерних объектов проверять перед реализацией.
