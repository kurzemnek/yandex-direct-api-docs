# 06. Создать, перечитать и согласовать фактическое состояние

[Начало](../START.md) · [Актуальность](../CURRENT.md) · [Спецификация](05-campaign-spec.md)

**Вход:** спецификация с актуальным независимым PASS именно по этой версии
и основаниям, выбранный реальный кабинет, разрешение на конкретные записи
и подтверждённые права. Пилот требует права на расходы.
**Политика агента:** сначала создание без показов, если lifecycle выбранного
типа это позволяет; затем чтение и сверка; включение — в пределах полномочий.

## Шаги

1. Повторно проверить клиента, среду, актуальные схемы, ограничения и состояние
   зависимых объектов. Перед записью получить снимок и сформировать diff.
2. Составить граф зависимостей конкретного типа: материалы/условия → кампания →
   группы → объявления и связи, в фактически требуемом API порядке.
   Не переносить этот пример на тип с другим контрактом.
3. **До первого add** доказать путь без показов: состояние новых объектов,
   модерация, даты, условия возможного старта и допустимые методы управления.
   `OFF` сам по себе не постоянный запрет: его причина может исчезнуть.
   Не считать отсутствие денег надёжным выключателем.
4. Если безопасный lifecycle не подтверждён, остановиться до записи и выдать
   спецификацию с конкретным блокером. «Создать, потом успеть остановить»
   не обеспечивает отсутствие показов. Не вызывать `suspend` для всех объектов
   автоматически: например, Ads.suspend недоступен объявлениям-черновикам.
5. Записать приватный журнал намерения **до отправки**: локальный operation key,
   отпечаток payload, клиент, сервис/версия, зависимости, ожидаемые объекты.
   Локальный ключ — не обещание серверной идемпотентности.
6. Выполнять ограниченные партии. Разбирать результат каждого элемента,
   предупреждения и ошибки, сохранять полученные ID и `RequestId`.
   HTTP 200 без разбора тела не доказывает успех всей партии.
7. При таймауте, обрыве соединения или потере ответа записать локальный исход
   `UNKNOWN` — неизвестно, применена ли запись. Это состояние журнала агента,
   отличное от одноимённых enum API. **Не повторять add вслепую.**
8. Провести reconcile: прочитать известные ID; для неизвестных найти кандидатов
   в правильном кабинете и родительском объекте, пройти страницы и сравнить
   доступные поля с намерением. Имя или временное совпадение не уникальный ключ.
   Несколько кандидатов — неоднозначность; пустая выборка после таймаута ещё
   не доказывает отсутствие записи. При неопределённости новые записи блокировать.
9. Повтор разрешать только после доказанной неуспешной операции/отсутствия эффекта
   либо по документированной семантике конкретного метода. Частично успешную
   партию продолжать по сверенным элементам, не пересоздавая успешные.
10. После записи выполнить readback: вся структура, стратегия/бюджет и единицы,
    гео, корректировки, условия, материалы, URL/UTM, цели, статусы и запрет показов.
    Сравнить со спецификацией; расхождения устранить или явно заблокировать пилот.
11. Если включение уже разрешено, нет блокеров и мониторинг готов, выполнить
    документированный для этих объектов переход к пилоту. Если разрешено лишь
    создание — сохранить проверенное состояние и конкретный результат для приёмки.
    Проверить чтением фактический переход; контролировать расходы и результаты
    по согласованным критериям с учётом задержки отчётов и оплат.

## Выход

Приватная квитанция: спецификация/diff, подтверждённые ID, поэлементные исходы,
readback, состояние показов, неопределённости, полномочия и следующий шаг.
`CREATED` без readback не равно «готово», отправка команды не равна её проверке.
В репозитории — только синтетический пример квитанции без токенов, ID и сумм.

## Критерии и блокеры

- Нет дубликатов от слепого retry; каждый `UNKNOWN` разрешён или блокирует продолжение.
- Нет непроверенных зависимостей, скрытых частичных ошибок и расхождений со спекой.
- Состояние без показов подтверждено по lifecycle, пилот укладывается в разрешение.
- Fixture проверяет алгоритм, но не подтверждает создание/остановку в реальном API.

Нет прав, неподдерживаемый тип, непонятное состояние, неоднозначный reconcile,
неподтверждённая остановка или неготовое измерение блокируют зависимые действия.
Не использовать удаление как универсальный откат: заранее проверить допустимость,
потерю истории и способ возврата для конкретного объекта.

## Проверенные основания API

[Campaigns.suspend](https://yandex.ru/dev/direct/doc/ru/campaigns/suspend)
действует на кампании; у [Ads.suspend](https://yandex.ru/dev/direct/doc/ru/ads/suspend)
есть ограничения по состоянию. Статусы описаны в
[кампании](https://yandex.ru/dev/direct/doc/ru/objects/campaign) и
[объявлении](https://yandex.ru/dev/direct/doc/ru/objects/ad).
Проверено 2026-11-12. Точный lifecycle каждого используемого типа и семантику
повтора метода подтвердить перед реализацией; это не универсальный скрипт запуска.
